# Portfolio site, Kristjan Mihin

Personal portfolio and freelance site. Owner: Kristjan Mihin, full-stack developer (.NET / Azure / React), Slovenia.

## Stack
- Astro (static output), Tailwind CSS, TypeScript.
- Client JS: three, gsap (ScrollTrigger, SplitText), lenis, loaded via <script> in Astro components. Keep scripts small and commented. No UI framework on the client.
- Design (v8, "Liquid"): a light page lit by soft fields of colour, around a body of liquid chrome and glass that flows down it; the interface is frosted glass over that light. One fixed Three.js canvas behind every page (`#scene` in `Base.astro`, `src/scripts/scene.ts`) paints all of it. The page itself is a "wall" in the scene (a plane hung on the camera, `WALL_SHADER`): three soft fields of coloured light drifting slowly (one follows the chrome), colours per chapter from `PALETTES` (each stop names one), the chrome's shadow and the glass ball's, with caustic light in them. The name plane uses the same shader. The chrome reaches for the mouse (a bump grows on the pointer's side, near drops lean to it) and a click shakes it and spins the ring; not on touch, not with reduced motion. Glass UI: `.glass` in `global.css` (`--glass-fill`, `--glass-edge`, `--glass-shadow`, a dark set under `html.on-dark`, a solid fallback for `prefers-reduced-transparency`): the header bar, `.btn-secondary`, the service cards (the first of four tinted orange), the frame of the featured screenshot and the case cover, the active skill, the case facts panel and the Next band. The chrome is eight "drops" drawn as metaballs (three's `MarchingCubes`, 64 cells a side, 44 on phones), a mirror with a thin iridescent film; around it a glass ring (`MeshPhysicalMaterial` with transmission and dispersion) and a small glass ball like a soap bubble that circles it. Reflections come from a studio painted on a canvas (`studioReflections`: light above, dark below and behind, white lamps, an orange glow right, a blue one left). `LAYOUTS` are the forms the drops take (one body, drift, column, seven, necklace, scatter, sphere, moons); `STOPS` say, per chapter, where the chrome is, its layout, how much the drops wander, what the ring and ball do, and whether the page is dark. Every section names its stop with `data-stop` (and `data-stop-late` for a second one inside the section); `motion.ts` (`followJourney`) tells the scene how far the scroll is between two stops and the drops ease there, so the chrome splits and merges with the scroll. Chapters: hero (one restless body in front of the name), about (a body with smaller ones drifting off), work (a column), skills (seven separate drops, one per skill: the active skill's drop swells and the ring settles around it, `setActiveDrop`), offer (a necklace, small, top right), closing (the page turns dark: a scatter of drops, "chaos", flows into one perfect sphere, "order"), contact (a calm body with moons), case pages ("detail", small, top right). The dark chapter: `scene.ts` sets `html.on-dark` and the wall eases to the night palette; `global.css` swaps every colour variable under `html.on-dark`. The name on the first screen is drawn inside the scene (a plane kept exactly over the page's own `h1`, which is transparent while `html.scene-on`), because glass only bends what is in the 3D scene. Phones: the chrome is large above the text on the first and last screen and peeks in at the top corner elsewhere (`NARROW_STOPS`). A slow machine gets a coarser chrome and a lower resolution after two seconds (`checkSpeed`). Without WebGL the canvas is hidden and the page works as plain HTML. Palette (`global.css` `@theme`, the fallback when the scene does not run): page #e5e4e0, surface #f2f1ed, ink #141518, muted #55575d, one accent orange #ff4d1a (as text: `accent-ink` #b4310a); dark chapter #0e0f12 with #ecebe6 type. Fonts (self-hosted via Fontsource): Mona Sans Variable for everything, using its width axis (the name at 125%, headings 110-112%), Geist Mono Variable for small labels and tags (`.label`, `.tag`). Shapes: buttons, the header bar and tags are pills; glass panels have a 20px corner, images in them 12px. Layout classes: `.wrap`, `.section`, `.heading`, `.heading-sm`, `.lead`, `.btn .btn-primary / .btn-secondary`, `.link`. Motion (`src/scripts/motion.ts`, GSAP ScrollTrigger + SplitText, Lenis smooth scroll): `data-split` (heading lines rise out of clipped boxes), `data-scrub` (a paragraph's words light up with the scroll), `data-enter` (appears when the page opens), `.reveal` (children fade up in turn), `data-count` (numbers count up), `data-unveil` (an image frame opens as it scrolls in), `data-pan` + `data-pan-track` (the services row moves sideways while pinned, wide screens only), `data-magnetic` (buttons lean to the pointer), the header hides on scroll down. Everything honours `prefers-reduced-motion` (no smooth scroll, no pinning, the chrome steps between stops and holds still). No custom cursor, no scroll cue, no section numbers. Content lives in `content/`; never hardcode case-study text in components.
- Copy rules: no em/en dashes in visible text (use commas, colons, periods, or a plain hyphen for ranges).
- Deploy target: Cloudflare Pages (static). Keep the build host-agnostic.

## Code conventions
- Simple, readable code. No clever abstractions.
- No inline styles. Tailwind utility classes or scoped component CSS.
- Small components, one responsibility each.
- Type all frontmatter with Astro content collections (`src/content.config.ts`).
- English UI. Slovenian translation may come later; keep strings in content, not in markup.

## Content rules
- The transport / logistics field I work in now is never named (I cannot take projects in that field): the e-CMR work is shown in general terms as `document-platform.md` ("Digital document exchange platform"), the ReBAC work as "Security, roles and rights for a B2B platform"; the carrier import stays hidden (`_carrier-data-import.md`, skipped by the collections). The apartment site is not named ("Holiday apartment website").
- Professional work (Trinet) is described anonymously: no client names, no screenshots with real data, no internal system names beyond what is in `content/professional/`.
- Side projects may link to GitHub repos.
- AI-assisted scaffolding (Lovable) is disclosed where used.

## Pages
- `/` is the whole site, one page: `#home` hero (`Hero.astro`: the name, one line, two buttons) -> `#about` (`About.astro`: portrait, the first sentence read word by word by the scroll, two paragraphs; `Facts.astro`: four figures counting up) -> `#work` Selected work (`Featured.astro`: the first own product with a cover image, large; `WorkList.astro`: the rest in two groups, professional work and own products, rows linking to the case study pages) -> `#skills` What I work with (`Expertise.astro`, from `content/skills.json`) -> `#offer` What I offer (`Offer.astro`, cards from `content/services.json`, a sideways row on wide screens) -> `#closing` (`Closing.astro`, the dark chapter, sticky for 250vh on wide screens) -> `#contact` (`Contact.astro`: the email as the main action, links, footer line; the home page passes `footer={false}` to Base).
- Work comes from the case-study collections (featured first, then most recent).
- `/work/[slug]` is a page for every case study: title, tagline and summary, the cover, the feature grid (`CaseFeatures.astro`), a sticky panel with role, stack tags and links beside the markdown body; a "Next" band and `Footer.astro`.
